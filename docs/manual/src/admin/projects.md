## After creation

A project administrator adapts the project under its **Settings** tab.

- **Details**: name, description and who can see it. *Everyone in the workspace* suits most work; choose *Only members listed below* for confidential matters such as legal or personnel work.
- **Members**: people, agents and groups with a project role.
- **Work item types**: select the types this project offers. Any type defined under [Types and workflows](schemes.md) can be added, so a software project can gain a *Risk* register or a purchasing project a *Decision* log. A type that already has items in the project cannot be turned off, and neither can the project's default type.
- **Cycles**: named time boxes for planning, such as *Sprint 12*. Mark a cycle *Active* when it starts and *Closed* when it ends.

Service desk projects have more settings: see [Service desk setup](service-desk.md).

## Conventions that help

- Give projects short, pronounceable keys. They appear in every item key, commit message and conversation.
- One project per team or product, not per person or per month. Use cycles and labels for time and themes.
- Use a private project only when the content requires it. Private work cannot be linked to or found by colleagues who might need it.
- Agree what *Done* means in each workflow and write it on a page in the project's space.
